## 3. App 测试资源

为避免把 26 张约 2 MB 的原图全部打包进 APK，测试版本做以下处理：

1. 从每张原图中心裁取主体区域，不包含边缘平台标识。
2. 缩放为 `512×512`。
3. 编码为 WebP（质量 88）。
4. 输出到 `app/assets/device_icons/`。
5. 资源命名统一为 `<type>_<state>.webp`，例如：
   - `light_bulb_off.webp`
   - `light_bulb_on.webp`
   - `light_bulb_offline.webp`

当前输出 26 个 WebP，约 0.5 MB。原始 `app/image/` 不作为正式 App asset，也不随本批代码提交。

### 显示规则

- 在线且关闭：`*_off.webp`
- 在线且开启：`*_on.webp`
- 离线：`*_offline.webp`
- 阀门离线图缺失：使用 `valve_off.webp`，同时沿用卡片离线半透明效果。
- 门铃、摄像头、继电器缺图：使用 Cupertino 内置图标。

## 4. 设备类型协议

Mesh 网关发布节点状态：

```text
office/light/node/<id>/status
```

新状态示例：

```json
{
  "id": "node-0B55C0",
  "online": true,
  "state": "on",
  "layer": 2,
  "role": "node",
  "type": "light_bulb"
}
```

当前支持的可配置节点类型：

| `type` | App 名称 | 当前控制语义 |
|---|---|---|
| `light_bulb` | 智能灯泡 | 开/关 |
| `ceiling_light` | 吸顶灯 | 开/关 |
| `light_strip` | 智能灯带 | 开/关 |
| `wall_switch` | 墙壁开关 | 开/关 |
| `socket` | 智能插座 | 开/关 |
| `relay` | 继电器 | 开/关 |
| `curtain_motor` | 窗帘电机 | 打开/关闭 |
| `valve` | 智能阀门 | 打开/关闭 |
| `door_lock` | 智能门锁 | 上锁/解锁 |
| `gateway` | Mesh 网关 | 状态和拓扑，不显示快速开关 |

兼容规则：旧节点没有 `type` 时，App 和新网关都按 `light_bulb` 处理。

## 5. 固件实现边界

- `internal_communication` 增加 Kconfig 设备类型选择，并把固定长度 `device_type` 附加在节点状态包末尾。
- 网关接受旧版短状态包，旧节点不会因为协议扩展而消失。
- 网关自己的节点记录固定上报 `type: gateway`。
- 当前所有执行器类型仍复用已有 on/off Mesh 指令；开发板 LED 只是控制结果指示。
- 真实插座继电器、窗帘电机、阀门和门锁驱动、电气保护、限位与安全逻辑尚未实现，不能把当前演示固件描述成量产执行器固件。

## 6. App 页面行为

- 首页门铃卡片：缺单图，暂用内置门铃图标。
- 网关摘要和网关详情：使用网关三态图片。
- 普通 Mesh 节点：按固件 `type` 和在线/开关状态选择图片。
- 首页不再把 root 网关重复显示为普通灯卡片。
- 设备详情页显示大图、设备类型、在线状态、Mesh 层级和快速开关。
- 不同类型显示对应扩展方向：
  - 灯具：亮度、色温、场景。
  - 插座/继电器/开关：定时、电量、联动、上电状态。
  - 窗帘：开合百分比、行程校准。
  - 阀门：开度、自动关闭、安全告警。
  - 门锁：临时密码、开锁记录、异常告警。

上述扩展项目前是产品页面占位，只有 on/off 指令已接入。
